# Guard map: every guard, the test that keeps the wrong out, the one that lets the right in, and its mutants

John's rule (2026-11-10): don't trust green checks. A guard is held only when (1) a test keeps the wrong out and a test
lets the right in, at the very limit, (2) both are named here, and (3) a planted bug turns them red. `tools/mutate.py`
plants each mutant of `tools/mutations.json` (138 of them) in a throwaway copy of the repo and runs its tests; one they
survive fails the run (`python tools/check.py --mutate`, CI's `mutation` job on every push and pull request).

A loosen mutant lets the wrong in (a check removed, a limit widened); a tighten mutant keeps the right out (a limit cut
one short, an allowed value refused). AH-155 started with 110 mutants of these 55 guards: 15 survived tests that were
all green. Each now has a test that fails with it, and new mutants hold what AH-155 changed (the TLS minimum, the
Origin list) and each limit's other side.

Paths in the Code column are where each mutant's text sits (line numbers from the AH-155 commit; rows 40, 44 and 56-58 from AH-158's); test files are under
`backend/tests/` unless named. A new or changed guard adds a row here and its loosen and tighten mutants in the same commit.
